# v2.1 — شمارنده‌محور، داوری منعطف‌تر، تایمر و Overview (روی تگ v2.0)

## تحلیل v2.0 (خلاصه)
**نقاط قوت:** ماشین‌حالت ۱..۱۲۶ (`core/sequence.py`) با جدول دقیق شما؛ FSM لحظه‌ای هر حرکت با باند «به نفع ورزشکار + پرچم بازبینی»؛ کالیبراسیون صحنه؛ تست‌های مصنوعی (mock) برای هر قانون.
**ضعف‌هایی که پیدا کردم:**
1. هر دو FSM همیشه روی همه‌ی فریم‌ها اجرا می‌شدند و «توالیِ» حرکت بعدی برای بازیابی استفاده می‌شد → نوعی تشخیص حرکت مستقل، نویز بین‌حرکتی.
2. شروع برپی فقط از حالت «کاملاً صاف» (`upright`) مسلح می‌شد؛ ایستادن خمیده/دست روی زانو باعث از‌دست‌رفتن تلاش می‌شد.
3. آستانه‌ها نزدیک آیین‌نامه بودند (فقط باند مرزی اعتبار می‌گرفت).
4. ساعت از تشخیص بیپ/حدس شروع می‌گرفت (اگر خطا کند، زمان کم/زیاد) و در حالت تایم‌کپ هیچ زمانی نمایش داده نمی‌شد؛ در UI تابع `fmtTime` با `Math.round(seconds % 60)` می‌توانست «01:60» بسازد.

## تغییرات
**۱) شمارنده‌محور** — `sequencer.sync_fsms` حالا فقط FSMِ حرکتِ «مورد انتظار» را فعال می‌کند. دو استثنای باریک (غیرطبقه‌بندی‌کننده) برای اینکه سیستم هیچ‌وقت کور نشود: (الف) هنگام آخرین اسلات هر فاز FSM بعدی هم مسلح می‌شود تا اولین رپِ بعد از سوییچ از دست نرود؛ (ب) اگر حرکت مورد انتظار ۳ ثانیه هیچ تلاشی نداد، FSM بعدی به‌عنوان «پروب» مسلح می‌شود (بازیابی توقف). بقیه غیرفعال و تلاش بازشان بی‌صدا حذف می‌شود. بعد از رپ ۱۲۶ همه خاموش‌اند.
**۲) داوری منعطف**
- یک دکمه: `EASE` (پیش‌فرض ۰٫۵؛ با `JUDGE_EASE` قابل تغییر؛ `0` = آیین‌نامه‌ی سخت). هر خط نو-رپ خودکار حدود ۵۰٪ از «لقیِ مرجع» دورتر شد:
  عمق اسکوات: هیپ تا ۰٫۰۷H بالاتر از زانو هنوز معتبر (قبلاً ۰٫۰۱۵H) · قفل آرنج: نو-رپ فقط زیر ۱۲۸° (قبلاً ۱۳۸°) · قفل زانو/لگن: زیر ۱۳۳° · قدم‌زدن: ۰٫۳۰H (قبلاً ۰٫۱۵H) · بالای سر: ۰٫۰۱۵H · فرود ناهم‌زمان برپی: ۰٫۴۲ ثانیه (قبلاً ۰٫۲۸) · عبور از بار: ۰٫۱۸H · «بدون پرش»: ۸ فریم (قبلاً ۴).
  **عمداً کم‌تر شُل شد:** سینه به زمین (۰٫۳۳H)، چون شانه‌ی بالای پلانک حدود ۰٫۳۰–۰٫۳۵H است و شل‌تر از آن برپیِ بدون پایین‌آمدن را معتبر می‌کند. پیشنهاد می‌کنم این یکی را سفت نگه داریم.
- **ایستادن خمیده:** آرمِ برپی با افت جناغ نسبت به «بالاترین جناغ در ۶ ثانیه‌ی اخیر» انجام می‌شود، نه صاف‌بودن؛ چون شمارنده می‌داند برپی است.
**۳) تایمر و Overview**
- ساعت از **فریم اول ویدیو** شروع می‌شود (`t=0`)؛ بیپ فقط با `JUDGE_USE_BEEP=1` فعال است؛ شروع دستی همچنان override می‌کند. کالیبراسیون ۲ ثانیه‌ی اول را بافر می‌کند و بعد همان فریم‌ها را به‌ترتیب داوری می‌کند (چیزی از دست نمی‌رود).
- کلاک **با رپ ۱۲۶ یا تایم‌کپ ۱۰:۰۰ (هرکدام زودتر) متوقف می‌شود**؛ اگر ورزشکار زودتر ایستاد، روی زمان آخرین رپ. در ویدیوی مرور هم کلاک روی همان لحظه یخ می‌زند (`FINISH/CAP/END`).
- `result.overview`: `reps_counted`, `no_reps`, `stop_time_text`, `stop_kind`, `line_fa/en`. کارت امتیاز و آمار، حتی در حالت کپ، زمان را نشان می‌دهند. باگ «۰۱:۶۰» اصلاح شد. ظاهر/قالب فرانت عوض نشده (فقط مقادیر).

## تست
۵۳ تست واحد + API/robustness پاس. تست‌های جدید در `tests/test_v21.py`. چهار تست قدیمی که خطاهای «مرزی» را نو-رپ می‌خواستند به خطوط جدید به‌روز شدند.

## محدودیت‌ها (صادقانه)
- روی ویدیوی واقعی اجرا نشده‌ام؛ `EASE=0.5` و بقیه‌ی اعداد باید با ویدیوهای واقعی وادکس محک بخورند (معیار: «نو-رپ اشتباه برای رپ درست» نزدیک صفر).
- اشکال «تایمر کم نشان می‌دهد» را روی ویدیوی واقعی بازتولید نکردم؛ طول خروجی ویدیوی مرور با ورودی برابر درآمد. محتمل‌ترین علت‌ها همان شروع ساعت از بیپ/حدس و باگ‌های فرمت بودند که اصلاح شد. اگر ویدیوی نمونه‌ی خراب را بفرستید دقیق‌تر بررسی می‌کنم.
- ایستادن خمیده فقط برای برپی لحاظ شد؛ تراستر تغییری نکرد.
- این نوبت جست‌وجوی تازه‌ی منابع انجام ندادم؛ تصمیم‌ها از تحلیل خودِ کد و تست‌هاست.

# v2.1.1 — بررسی کامل مسیر آپلود ← آنالیز ← Overview

## علت خطای «The video file is not readable (ffprobe)»
تابع `probe` هر خطا را قورت می‌داد؛ یعنی اگر **ffprobe/ffmpeg روی سیستم نصب نباشد (بسیار محتمل روی مک)** یا فایل خراب باشد، هر دو یک پیام می‌دادند. حالا:
- نبودِ ابزار با پیام جدا و قابل‌اقدام اعلام می‌شود (`brew install ffmpeg`)، و `/api/health` مقدار `ffmpeg_ok / ffprobe_ok` را هم نشان می‌دهد (در UI «Engine online» تنها کافی نبود).
- اعتبارسنجی ویدیو **همان لحظه‌ی آپلود** انجام می‌شود (نه بعد از زدن Analyze)؛ خطا دوزبانه (EN / FA) و سریع نمایش داده می‌شود.

## باگ‌هایی که حین بررسی پیدا و درست شد
1. **ویدیوی عمودی موبایل (iPhone/Android):** ابعاد از متادیتای چرخش نادیده گرفته می‌شد، ولی ffmpeg ویدیو را خودکار می‌چرخاند ⇒ اندازه‌ی فریم اشتباه و تصویر خراب به مدل پوز می‌رسید. حالا ابعاد «نمایشی» (چرخیده) استفاده می‌شود (تست با ویدیوی چرخیده).
2. ویدیوهای بدون هدر مدت (WebM ضبط‌شده در مرورگر): مدت از تگ/آخرین پکت محاسبه می‌شود نه صفر.
3. سقف حجم **۵۰۰ مگابایت** (قبلاً ۳ گیگ) در سرور؛ پیام‌ها به MB. در فرانت هم پیش از آپلود حجم (>۵۰۰MB) و مدت (>۱۵ دقیقه، در حد توان مرورگر) چک می‌شود.
4. سقف ۱۵ دقیقه (تا ۹۰۰ ثانیه دقیقاً پذیرفته؛ ۹۶۰ ثانیه رد می‌شود)، حداقل رزولوشن ۴۸۰p، فایل خراب ⇒ رد با پیام روشن. همه تست خودکار با ویدیوی واقعی دارند (`tests/test_ingest.py`).

## اجرا روی مک
```
brew install ffmpeg          # الزامی (ffmpeg + ffprobe)
cd mini-services/crossfit-judge && pip install -r requirements.txt && python main.py
# ترمینال دوم، ریشه‌ی پروژه:
bun install && bun run dev    # یا npm install
```
نکته‌ی `npm install`: package.json همین بسته را در یک پوشه‌ی تمیز resolve کردم و `inotify` در آن **نیست**. اگر خطای `inotify` دیدی، آن از `package.json`/`package-lock.json` یا `node_modules` قدیمی همان پوشه‌ی خودت است: `rm -rf node_modules package-lock.json` و دوباره نصب کن.

## چیزی که هنوز نتوانستم بررسی کنم
مرحله‌ی استخراج پوز با MediaPipe روی ویدیوی واقعی (مدل `.task` در محیط من قابل دانلود نبود). مسیر ویدیو ← فریم ← آنالیز با شبیه‌ساز، و آپلود/اعتبارسنجی/چرخش/مدت با ویدیوی واقعی تست شده‌اند.
