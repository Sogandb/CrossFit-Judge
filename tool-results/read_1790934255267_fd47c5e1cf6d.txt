    50→    50→- Title area? → Need for hero header
    51→    51→- Comparison data? → Need for bar chart
    52→    52→

    55→    55→## Step 2: Layout Decision
    56→    56→
    57→    57→### 2.1 Flowchart Layout Decision Tree
    58→    58→
    59→    59→```
    60→    60→⚠️ DEFAULT RULE: When user asks "generate/create XXX 流程图" without specifying format,
    61→    61→   DEFAULT to Layout C (Phased Vertical). Almost all real-world processes have phases.
    62→    62→
    63→    63→User specified Mermaid/markdown?
    64→    64→  └─ Yes → Follow user choice (Format Constraint Rule)
    65→    65→  └─ No →
    66→    66→      nodeCount ≤ 6 AND no phases AND maxTextLen ≤ 8 (CJK)?
    67→    67→        └─ Yes → Mermaid (minimal flowchart)
    68→    68→        └─ No →
    69→    69→            phaseCount > 0 OR nodeCount ≥ 5?
    70→    70→              └─ Yes → ⭐ Layout C: CSS Phased Vertical flowchart (DEFAULT)
    71→    71→              └─ No →
    72→    72→                  hasRoles?
    73→    73→                    └─ Yes → Layout D: CSS Dual-panel/Swimlane flowchart
    74→    74→                    └─ No → Layout C: CSS Phased Vertical flowchart (fallback also uses C)
    75→    75→```
    76→    76→
    77→    77→**⚠️ Layout A (Grid) and Layout B (Snake) are only for very special scenarios (e.g., flat comparison, unordered parallel items). Flowcharts default to Layout C.**
    78→    78→
    79→    79→### 🚫 Flowchart Anti-Patterns (FORBIDDEN)
    80→    80→
    81→    81→| ❌ Bad Pattern | ✅ Correct Pattern |
    82→    82→|---|---|
    83→    83→| Phase titles (一、二、三...) as isolated left-side text labels | Phase titles as colored title bars, wrapped inside group cards |
    84→    84→| All nodes flat-laid in Grid without group containers | Each phase wrapped in a `.phase-group` card containing its steps |
    85→    85→| Role labels scattered above nodes | Role info displayed uniformly at the top of the flowchart, or as phase card labels |
    86→    86→| Nodes connected with loose diverging lines | Phases connected with arrows (↓), steps within phases use numbering |
    87→    87→| Inconsistent node sizes, uneven spacing, misaligned | Same-phase nodes share uniform style, overall alignment consistent |
    88→    88→| Using Layout A Grid for a phased flowchart | Has phases → must use Layout C |
    89→    89→
    90→    90→### 2.2 Canvas Size Calculation
    91→    91→
    92→    92→```python
    93→    93→def calc_flowchart_canvas(node_count, max_text_len, parallel_count, has_roles, layout):
    94→    94→    node_width = max(180, max_text_len * 16)  # ~16px per CJK char (including padding)
    95→    95→    
    96→    96→    if layout == 'snake':
    97→    97→        cols = min(4, node_count)
    98→    98→        rows = (node_count + cols - 1) // cols
    99→    99→        width = cols * (node_width + 60) + 120   # 60=gap, 120=padding
   100→   100→        height = rows * 120 + 200                 # 120=row height
   101→   101→    elif layout == 'dual-panel':
   102→   102→        width = max(1600, node_width * 2 + 400)   # left panel + right flow
   103→   103→        height = node_count * 100 + 200
   104→   104→    elif layout == 'phased-vertical':
   105→   105→        width = max(800, node_width + 200)
   106→   106→        height = node_count * 80 + 200
   107→   107→    else:  # grid
   108→   108→        cols = max(parallel_count, 2)
   109→   109→        width = cols * (node_width + 60) + 120
   110→   110→        rows = (node_count + cols - 1) // cols
   111→   111→        height = rows * 120 + 200
   112→   112→    
   113→   113→    return max(width, 800), max(height, 600)
   114→   114→```

   116→   116→### 2.3 Color Decision
   117→   117→
   118→   118→**Iron rule: Node background = low-saturation light color, border = high-saturation color. Large high-saturation areas = children's drawing.**
   119→   119→
   120→   120→**⚠️ Text contrast iron rule: Dark/accent background nodes must use light text (white or near-white) for title and description.**
   121→   121→Light background → dark text (`#1F2937`), dark background → light text (`#FFFFFF` or `#FFF7ED`).
   122→   122→Common mistake: Endpoint/highlight node switched to dark background, but description text remains dark gray, making it completely unreadable.
   123→   123→
   124→   124→```
   125→   125→Node type → color:
   126→   126→  Start/end  → bg: #EFF6FF, border: #3B82F6 (blue), text: #1E40AF
   127→   127→  Normal step  → bg: #F8FAFC, border: #94A3B8 (gray-blue), text: #374151  or colored by phase
   128→   128→  Decision node  → bg: #FFF7ED, border: #F59E0B (amber), text: #92400E
   129→   129→  Success/pass → bg: #F0FDF4, border: #10B981 (green), text: #065F46
   130→   130→  End/failure → bg: #F5F3FF, border: #8B5CF6 (purple), text: #5B21B6
   131→   131→  Emphasis/endpoint (dark bg) → bg: #92400E, border: #F59E0B, text: #FFFFFF, desc: #FFF7ED
   132→   132→
   133→   133→Max 3-4 background colors for nodes in the same flowchart.
   134→   134→Overall chart background = white #FFFFFF.
   135→   135→```
   136→   136→
   137→   137→**Phase bar colors**: Same-hue gradient (blue-gray family), **never use different hues per phase**.
   138→   138→
   139→   139→```css
   140→   140→/* ✅ Same-hue blue-gray progression */

   159→   159→

   352→   352→### Auto Connector Script
   353→   353→
   354→   354→```javascript
   355→   355→// connections = [['sourceID', 'targetID', 'label'], ...]
   356→   356→function drawConnectors(connections) {
   357→   357→  const svg = document.getElementById('connectorSvg');
   358→   358→  const container = svg.parentElement;
   359→   359→  const cRect = container.getBoundingClientRect();
   360→   360→  
   361→   361→  svg.setAttribute('width', cRect.width);
   362→   362→  svg.setAttribute('height', cRect.height);
   363→   363→  svg.setAttribute('viewBox', `0 0 ${cRect.width} ${cRect.height}`);
   364→   364→  
   365→   365→  // Clear old connectors (keep defs)
   366→   366→  svg.querySelectorAll('line, path, text.connector-label').forEach(el => el.remove());
   367→   367→  
   368→   368→  connections.forEach(([fromId, toId, label]) => {
   369→   369→    const fromEl = document.querySelector(`[data-id="${fromId}"]`);
   370→   370→    const toEl = document.querySelector(`[data-id="${toId}"]`);
   371→   371→    if (!fromEl || !toEl) return;
   372→   372→    
   373→   373→    const f = fromEl.getBoundingClientRect();
   374→   374→    const t = toEl.getBoundingClientRect();
   375→   375→    const x1 = f.left + f.width/2 - cRect.left;
   376→   376→    const y1 = f.bottom - cRect.top;
   377→   377→    const x2 = t.left + t.width/2 - cRect.left;
   378→   378→    const y2 = t.top - cRect.top;
   379→   379→    
   380→   380→    if (Math.abs(x1 - x2) < 10) {
   381→   381→      // Same column → straight line
   382→   382→      const line = document.createElementNS('http://www.w3.org/2000/svg', 'line');
   383→   383→      line.setAttribute('x1', x1); line.setAttribute('y1', y1);
   384→   384→      line.setAttribute('x2', x2); line.setAttribute('y2', y2);
   385→   385→      svg.appendChild(line);
   386→   386→    } else {
   387→   387→      // Different column → bent line
   388→   388→      const midY = (y1 + y2) / 2;
   389→   389→      const path = document.createElementNS('http://www.w3.org/2000/svg', 'path');
   390→   390→      path.setAttribute('d', `M ${x1} ${y1} L ${x1} ${midY} L ${x2} ${midY} L ${x2} ${y2}`);
   391→   391→      svg.appendChild(path);
   392→   392→    }
   393→   393→    
   394→   394→    if (label) {
   395→   395→      const text = document.createElementNS('http://www.w3.org/2000/svg', 'text');
   396→   396→      text.setAttribute('x', (x1 + x2) / 2);
   397→   397→      text.setAttribute('y', (y1 + y2) / 2 - 6);
   398→   398→      text.setAttribute('class', 'connector-label');
   399→   399→      text.textContent = label;
   400→   400→      svg.appendChild(text);
   401→   401→    }
   402→   402→  });
   403→   403→}
   404→   404→
   405→   405→// SVG defs (arrow definitions)
   406→   406→function ensureArrowDef(svg) {
   407→   407→  if (svg.querySelector('#arrowhead')) return;
   408→   408→  const defs = document.createElementNS('http://www.w3.org/2000/svg', 'defs');
   409→   409→  defs.innerHTML = '<marker id="arrowhead" markerWidth="10" markerHeight="7" refX="9" refY="3.5" orient="auto"><polygon points="0 0, 10 3.5, 0 7" fill="#94A3B8" /></marker>';
   410→   410→  svg.appendChild(defs);
   411→   411→}
   412→   412→```

   459→   459→## Layout B: Snake Flowchart (>4 Linear Steps)
   460→   460→
   461→   461→For: Linear non-branching processes with many steps (5-20).
   462→   462→
   463→   463→### Key Rules
   464→   464→
   465→   465→- Max 4 nodes per row
   466→   466→- First row left→right, second row right→left (snake pattern)
   467→   467→- End-of-row to next-row turn connectors use bend lines, with ≥60px clearance at turns
   468→   468→- Node positions in grid are auto-calculated by JS (no manual grid-column)
   469→   469→
   470→   470→### Snake Layout Generation Script
   471→   471→
   472→   472→```javascript
   473→   473→function layoutSnake(nodeIds, cols) {
   474→   474→  cols = cols || 4;
   475→   475→  nodeIds.forEach((id, i) => {
   476→   476→    const row = Math.floor(i / cols);
   477→   477→    const colInRow = i % cols;
   478→   478→    const col = row % 2 === 0 ? colInRow + 1 : cols - colInRow; // Even rows L→R, odd rows R→L
   479→   479→    const el = document.querySelector(`[data-id="${id}"]`);
   480→   480→    if (el) {
   481→   481→      el.style.gridRow = row + 1;
   482→   482→      el.style.gridColumn = col;
   483→   483→    }
   484→   484→  });
   485→   485→}
   486→   486→```

   490→   490→## Layout C: Phased Vertical Flowchart (⭐ DEFAULT for all flowcharts)
   491→   491→
   492→   492→**This is the DEFAULT layout for flowcharts.** When the user asks for any flowchart without specifying format, use this layout.
   493→   493→
   494→   494→For: Any process with phases/stages, which is nearly ALL real-world processes (manufacturing, legal, project management, business operations, etc.). Also the safe fallback when unsure.

   713→   713→## Advanced Connector Rules
   714→   714→
   715→   715→### Many-to-One Convergence
   716→   716→
   717→   717→When multiple lines converge into one node, use the "merge first, then enter" pattern:
   718→   718→
   719→   719→```
   720→   720→[A] ──┐
   721→   721→[B] ──┤── → [目标]
   722→   722→[C] ──┘
   723→   723→```
   724→   724→
   725→   725→Implementation: Source lines reach a relay x-coordinate, merge into one vertical line, then a single line enters the target.
   726→   726→
   727→   727→### Cross-Layer Connector Avoidance
   728→   728→
   729→   729→If other nodes block the path between two nodes, **do not draw a straight line through them**.
   730→   730→
   731→   731→Priority:
   732→   732→1. **Redesign hierarchy** (best) — Most cross-layer lines indicate hierarchy design issues; connect adjacent layers only
   733→   733→2. **Detour line** — Route around middle nodes via canvas edge (offset 40px right)
   734→   734→3. **Thread through gap** — If middle-layer node gap ≥ 40px, route through the gap
   735→   735→
   736→   736→### Connector Alignment
   737→   737→
   738→   738→- Multiple lines from the same node start at a consistent position on the node border
   739→   739→- Use only one connector style per chart (right-angle/curved/straight), no mixing
   740→   740→- Connector label positions must be consistent (all above line or all centered)
   741→   741→
